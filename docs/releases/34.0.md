## What's new

### The dashboard is now a separate program

- The Crontab Guru Dashboard is now `crontab-dashboard`, a second program in each release. The `cronitor` binary no longer contains the dashboard, its web frontend or its MCP server. The CLI build no longer needs Node or npm.
- **If you use `cronitor dash`, install `crontab-dashboard` in the same folder as `cronitor`.** Without it, `cronitor dash` stops with exit code 1 and prints the command to install it, for example:

  ```
  curl -fsSL https://github.com/cronitorio/cronitor-cli/releases/download/34.0/crontab-dashboard_linux_amd64.tar.gz | sudo tar -xz -C /usr/local/bin
  ```

- Nothing else changes. `cronitor dash` starts `crontab-dashboard` with the same arguments, environment and configuration. systemd units, MCP settings (`cronitor dash --mcp-instance ...`), `/etc/cronitor/cronitor.json` and your cron jobs keep working. You can also run `crontab-dashboard` directly; it takes the same flags. `crontab-dashboard configure` and `crontab-dashboard update` work like the `cronitor` commands.
- `cronitor update` also updates `crontab-dashboard` when it is in the same folder. The dashboard's update button updates both programs.
- Release assets: `crontab-dashboard_<os>_<arch>.tar.gz` (Windows: `.zip`) for the same platforms as `cronitor`. The `cronitor` archives keep their names.
- The `dockerfile` installs both programs and starts `crontab-dashboard`.

### Other changes

- CI: the jobs that use the live API key no longer install npm packages. A separate job builds the frontend and runs `tests/dashboard-smoke.sh`. The `e2e` label also runs `tests/real-cron-dashboard.sh`, which turns monitoring on and off through the dashboard and checks real cron runs and pings.
