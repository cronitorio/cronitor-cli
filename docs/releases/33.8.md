## What's new

- Configure the telemetry endpoint with `CRONITOR_PING_API_HOST`, `--ping-api-host`, or `cronitor configure --ping-api-host`. For latency-sensitive workloads in Europe, use `eu.cronitor.link`. The default remains `cronitor.link`; this setting changes where pings are received, not data residency.
- Cronitor telemetry hosts retain the `cronitor.io` retry fallback. Custom hosts, such as private proxies, are used for every attempt.
- Fixed the dashboard Dockerfile to extract the release archive and select the correct binary for `amd64`, `arm64`, and `arm` containers.
- Added `compose.dashboard.yml` with runtime dashboard credentials, persistent volumes, and a localhost-only port binding. Supply `CRONITOR_DASH_USER` and `CRONITOR_DASH_PASS` when starting the container.
