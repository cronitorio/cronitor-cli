## What's new

### Rerunning `cronitor sync`

Sync is now safe and quiet to run again on a crontab it already set up ([#90](https://github.com/cronitorio/cronitor-cli/pull/90)). This applies to Linux and macOS. Windows scheduled-task sync works as before; its menu now shows every option at once and lists the keys, and Ctrl+C, `q` and Esc still skip one task.

- Sync asks only about jobs that are not monitored yet. To be asked about every job, for example to rename one, run `cronitor sync --with-monitored`. `--auto` ignores that flag.
- Plain `cronitor sync` is the normal way to rerun. It checks every monitored job against Cronitor and picks up schedule and timezone changes without asking about the job.
- For a job that is already monitored, sync sends only what changed: the schedule, the timezone, and the alert list when you pass `--notification-list`. Before, every sync replaced tags set in Cronitor with `cron-job` and reset alert lists to `default`.
- A changed `CRON_TZ` or `TZ` line now updates the monitor's timezone even when the schedule stays the same. Before, sync missed it.
- `cronitor sync --auto` asks nothing: it monitors every new job, sends schedule and timezone changes, and writes the crontab. Use it for scripts, not to pick up one schedule change.
- The name in Cronitor wins. Sync no longer sends the name from a `# Name:` comment for a monitored job, so a rename in the dashboard stays. If the comment differs, sync updates it.
- If a monitor was deleted in Cronitor, sync warns and does not create it again. Sync cannot tell a deleted monitor from one that never existed, so a hand-written `CRONITOR=new-key` line for a monitor you have not created gets the same warning: create the monitor first, or remove the key and let sync add it.
- Hand-written lines such as `CRONITOR=prune-events` now show the monitor's name from Cronitor.
- If sync cannot load your monitors, it warns. It then asks about every job (with `--auto`, it asks nothing) and sends each monitored job's schedule, because it cannot compare them.

### One summary, one question

- Sync now goes through every crontab first. Then it shows one summary per crontab (for example `1 new · 1 updated · 12 unchanged`), with one line for each updated job (for example `L3  Nightly backup: schedule 0 2 * * * → 30 3 * * *`), and asks `Apply these changes? [Y/n]` once. Before, each crontab was sent and saved as soon as you answered its questions.
- If nothing changed, sync says so and asks nothing.
- `--auto` applies without asking, as before.

### Menu

- New item: "Skip this job, don't ask again". It adds `# cronitor: ignore` above the line. Delete the comment to undo.
- Enter selects, `s` skips, and `q`, Esc, Ctrl+C or Ctrl+D quit. After you quit, sync asks whether to save the answers you gave so far.
- **Changed:** Ctrl+C now quits. Before, it skipped the job. `q` and Esc also skipped the job by mistake.
- Every option shows at once, with the keys listed below the menu.
- The job box fits the terminal and wraps long commands.

### Other changes

- **Changed:** `cronitor sync --dry-run` now sends nothing to Cronitor. It shows what would change and does not write the crontab. Before, it created and updated monitors.
- Without `sudo`, sync prints one hint at the end when system crontabs have jobs it could not check, instead of one warning for each file.
