## What's new

### Rerunning `cronitor sync`

Sync is now safe and quiet to run again on a crontab it already set up ([#90](https://github.com/cronitorio/cronitor-cli/pull/90)). This applies to Linux and macOS.

- Sync asks only about jobs that are not monitored yet. To be asked about every job, for example to rename one, run `cronitor sync --with-monitored`. `--auto` ignores that flag.
- Plain `cronitor sync` is the normal way to rerun. It checks every monitored job against Cronitor and picks up schedule and timezone changes without asking about the job.
- For a job that is already monitored, sync sends only what changed: the schedule, the timezone, and the alert list when you pass `--notification-list`. Without that flag, existing alert lists are kept and new monitors get Cronitor's default. Before, every sync replaced tags set in Cronitor with `cron-job` and reset alert lists to `default`.
- A changed `CRON_TZ` or `TZ` line now updates the monitor's timezone even when the schedule stays the same. Before, sync missed it.
- `cronitor sync --auto` asks nothing: it monitors every new job, sends schedule and timezone changes, and writes the crontab. When you pass a single crontab file, it prints that crontab to stdout even if nothing changed (and on `--dry-run`). Once sync has read the file, a failure prints the original crontab and exits 1. A direct `| crontab -` pipe can still install an empty crontab if sync fails before it can read the file, for example when the file is missing or a flag is invalid. Capture the output first: `out=$(cronitor sync --auto file) && printf '%s\n' "$out" | crontab -`. Do not add `--silent` to that command: `--auto --silent` prints no crontab, so the pipe would install an empty one. Use it for scripts, not to pick up one schedule change.
- `--dry-run` on a single named file that can't be written now exits 1.
- If any crontab fails to apply, in any mode (interactive or `--auto`, one crontab or several), sync now exits 1. Before, it exited 0.
- `--silent` hides status messages. On an interactive run it still asks `Apply these changes?` before sending or writing, so a monitored job's schedule cannot change with no confirmation. Combined with `--auto`, it also skips printing the crontab.
- The name in Cronitor wins. Sync no longer sends the name from a `# Name:` comment for a monitored job, so a rename in the dashboard stays. If the comment differs, sync updates it. It does not add a new `# Name:` comment.
- If a monitor was deleted in Cronitor, sync warns and does not create it again. Sync cannot tell a deleted monitor from one that never existed, so a hand-written `CRONITOR=new-key` line for a monitor you have not created gets the same warning: create the monitor first, or remove the key and let sync add it.
- Hand-written lines such as `CRONITOR=prune-events` now show the monitor's name from Cronitor.
- If sync cannot load your monitors, it warns. It then asks about every job (with `--auto`, it asks nothing) and sends each monitored job's schedule, because it cannot compare them. It does not rename monitors or add `# Name:` comments.

### One summary, one question

- Sync now goes through every crontab first. Then it shows one summary per crontab (for example `1 new · 1 updated · 12 unchanged`), with one line for each updated job (for example `L3  Nightly backup: schedule 0 2 * * * → 30 3 * * *`), and asks `Apply these changes? [Y/n]` once. Before, each crontab was sent and saved as soon as you answered its questions.
- If nothing changed, sync says so and asks nothing.
- `--auto` applies without asking, as before. `--auto --dry-run` prints the summary to stderr and the planned crontab to stdout.

### Menu

- New item: "Skip this job, don't ask again". It adds `# cronitor: ignore` above the line. A monitored job keeps reporting to Cronitor; sync just stops updating it. Delete the comment to undo.
- Enter selects, `s` skips, and `q`, Esc, Ctrl+C or Ctrl+D quit. While typing a name, `s` and `q` type normally, Esc goes back, and Ctrl+C or Ctrl+D quit. After you quit, sync shows the summary and asks whether to save the answers you gave so far.
- **Changed:** Ctrl+C now quits. Before, it skipped the job. `q` and Esc also skipped the job by mistake.
- Every option shows at once, with the keys listed below the menu.
- The job box fits the terminal and wraps long commands.

### Windows scheduled tasks

Windows scheduled-task sync works as before: it still asks about every task, sends the full monitor, and `--dry-run` still sends (it only skips rewriting the task). The shared menu now shows every option at once and lists the keys. `q`, Esc and Ctrl+C still skip one task; Ctrl+D still stops without a save prompt. "Don't ask again" is not offered, because that flow cannot persist `# cronitor: ignore`.

### Other changes

- **Changed:** `cronitor sync --dry-run` now sends nothing to Cronitor for Linux and macOS crontab sync. It shows what would change and does not write the crontab. Before, it created and updated monitors. `--file` imports and Windows scheduled-task sync still send.
- Without `sudo`, sync prints one hint at the end when system crontabs have jobs it could not check, instead of one warning for each file.
